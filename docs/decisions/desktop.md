# Десктопный клиент: окно, прокси, Linux

- **Состояние окна Electron восстанавливается при запуске** (`window-state.json`, поле `mode`: `normal`/`minimized`/`tray`): после перезагрузки машины или установки обновления приложение возвращается туда, где его оставили. Режим пишется на КАЖДОЕ изменение (`minimize`/`restore`/`hide`/`show`), а не при выходе: перезагрузка и `quitAndInstall` завершают процесс помимо нашей воли, и «сохраню при закрытии» не сработало бы. `mode: 'tray'` означает не показывать окно вовсе — показать и тут же спрятать значит моргнуть окном на весь экран при каждом старте с автозагрузки. Геометрия у свёрнутого/спрятанного окна НЕ перезаписывается: Windows уводит свёрнутое окно за экран, и `getBounds()` вернул бы мусорные координаты, с которыми окно потом открылось бы вне видимой области.

**Прокси и Linux в десктопном клиенте (1.11.7 → 1.11.12, 30.08 → 01.09.2026)**
- Три режима прокси: «Системный» (`mode: 'system'` — доверять тому, что настроено в ОС; на Linux читает gsettings, резерв — `http_proxy`/`https_proxy`), «Вручную» (`fixed_servers`) и «ЦИТ».
- **PAC-скрипт ЦИТ зашит в бинарь строкой** (`CIT_PAC_SCRIPT` в `main.js`) и подставляется через `data:`-URL. Ссылка на `http://i.tatar.ru/wpad.dat` не работала принципиально: Chromium должен сам скачать PAC по сети, прежде чем понять, как ходить в сеть, — а прокси нужен ровно тогда, когда сеть уже не работает. Цена: правила ЦИТ теперь обновляются только пересборкой клиента.
- Логин/пароль относятся **к прокси-серверу, а не к режиму** — иначе в «Системном» сохранённые креды не подставлялись бы, хотя тот же прокси их требует. Обработчик `session.on('login')` обязан проверять `authInfo.isProxy`: то же событие приходит и для Basic-авторизации обычных сайтов.
- Автовключение ЦИТ по IP `10.1.x.x` — **только на Linux**. На Windows прокси обычно уже в системе, и автовключение спорило бы с явным выбором. Флаг `userTouched`: тронул настройку руками — автоопределение больше не вмешивается.
- **Автозагрузка на Linux — свой `.desktop` в `~/.config/autostart/`.** `app.setLoginItemSettings()` документирован как Windows/macOS-only: на Linux он молча ничего не делает, а `getLoginItemSettings()` всегда возвращает `false` — переключатель выглядел рабочим и не работал никогда. `Exec` берётся из `process.execPath`, поэтому одинаково верен и для `.deb`, и для распакованного `tar.gz`.
- **Автообновление доведено до Linux** отдельным путём (`checkLinuxUpdate`): читает `linux.json`, качает пакет с прогрессом и открывает его системным обработчиком. `canUpdate` по-прежнему `win32` — это про `electron-updater`, а не про «на Linux обновлений нет».
