# Производительность

> **Поправка от 07.09.2026.** Известная неточность обрезки («встреча в 10:30»
> теряла хвост) исчезла вместе с кодами `:name:`: огрызком теперь считается только
> то, что начинается с `e~`, и совпадений с человеческим текстом не остаётся.
> Замеры сжатия ниже актуальны; свежие цифры сборки — в `docs/BASELINE.md`.

**Производительность выдач и сборки**
- **Сжатие включено 07.09.2026 отдельным файлом `/etc/nginx/conf.d/gzip.conf`** (не правкой `nginx.conf`: тот обслуживает ещё два чужих проекта, а откат тут — просто удалить файл). До этого стоял только `gzip on;` без `gzip_types`, а умолчание nginx — `text/html`, поэтому не сжимались ни JSON, ни JS. Замерено на живом трафике: `main.js` 795 → 220 КБ (−73%), `main.css` 227 → 38 КБ (−84%), `/api/emoji/catalog` **1 325 237 → 140 380 байт (−89%)** — один и тот же запрос настоящего клиента до и после. Холодная загрузка ~2.3 МБ → ~400 КБ.
- **`gzip_proxied any` в этом файле обязателен и не для красоты**: умолчание `off` означает, что nginx НЕ сжимает ответы на запросы с заголовком `Via`, то есть пришедшие через прокси. Без него сжатия не получили бы ровно те, у кого канал хуже всех — сотрудники за прокси ЦИТ. Бинарники (`.exe`, `.apk`) в `gzip_types` намеренно не входят: они уже сжаты.
- Отчёт CRA о размере бандла — это размер ПОСЛЕ gzip. Пока сжатия не было, он вводил в заблуждение вдвое.
- **`emoji_changed` рассылается на ЛЮБУЮ правку в панели**, и клиент по нему перечитывает `/emoji/catalog`. Раньше правки были редкими, новая панель делает их частыми. НО цена меньше, чем кажется на первый взгляд: по логу nginx видно, что каталог запрашивается УСЛОВНО и почти всегда отдаёт `304` с нулевым телом — полный ответ платится только при первой загрузке или реальной смене каталога. Плюс он теперь сжат до 140 КБ. Дельта вместо «перечитай всё» остаётся правильным решением, но гнаться за ней как за пожаром не нужно — и менять контракт события нельзя резко: в логе рядом с 1.11.18 живут клиенты 1.11.15.
- Панель управления грузится по требованию (`React.lazy` в `App.tsx`): она открывается одним человеком, а ехала в общем бандле всем. Главный кусок 850 → 750 КБ, панель вынесена в отдельный чанк ~96 КБ.
- Ручки правки смайликов возвращают полный каталог в ответе, поэтому панель НЕ перечитывает его вторым запросом. До этого на каждое нажатие уезжало 2.6 МБ дважды.

**Итог полной проверки (07.09.2026)**
- Целостность боевых данных идеальна: 0 элементов без пака, 0 ресурсов без элемента, 0 дублей `unicode_key`/`name`, 0 невидимых смайликов, **0 битых ссылок на 6317 файлов**, 0 групп с испорченной политикой, 0 сообщений без автора.
- На диске 1468 файлов-сирот (9.2 МБ) — исторический осадок. **Утечки нет**: проверено опытом, повторный импорт 1400 файлов дал прирост ноль, старые удаляются корректно.
- Одно сообщение ссылается на удалённый стикер и корректно деградирует через `sticker_fallback` — механика работает как задумана.
- Шаблон «оборванный код в конце строки» сведён в одно определение (`server/utils/shortcode.js`). Две копии разъехались с появлением `:e~<ключ>~<пак>:`, и серверная обрезка резала такой код посередине — в базе уже лежали два сообщения с ним. Клиентская пара (`trimDanglingShortcode`) остаётся отдельной по языку; при правке одного значения второе обязано меняться вместе с ним. Известная неточность, закреплённая тестом: хвост после двоеточия срезается и когда это не код («10:30» в конце ОБРЕЗАННОЙ строки неотличимо от начала `:30sec:`).
